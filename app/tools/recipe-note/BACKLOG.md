## 구현 중 발견

- [ ] **단위 사전 확장** — 현재 32종. `공기`·`그램`·`리터`·`토막`·`자밤` 등 실사용 로그를 보고 늘린다. 사전에 없어도 원문은 그대로 남고 "직접 고르기"로 잡을 수 있으므로(`물 500 그램` 확인) 데이터가 깨지지는 않는다 — 자동 선택이 안 될 뿐이다.
- [ ] **8분모 근사 분수** — 현재 후보는 `1/4 1/3 1/2 2/3 3/4`뿐. `0.375`(= 3/8) 같은 값이 `0.38`로 떨어진다. 실사용에서 자주 나오면 `1/8 3/8 5/8 7/8` 추가 검토.
- [ ] **꼬리 수사가 붙는 양** — `국간장 1큰술 반`·`물 한 컵 반`은 앞의 `1큰술`/`한 컵`만 잡히고 뒤의 `반`이 빠진다. ×2면 `2큰술 반`이 되어 값이 틀린다. 꼬리까지 물리려면 문법이 커지므로 지금은 수동 지정에 맡긴다.
  (`1 1/2컵` 대분수는 **이미 정상 동작**한다 — qty 1.5, ×2 → `3컵`. 2026-08-14 실측.)
- [ ] **수량이 앞에 오는 형태** — `1/2 양파`처럼 `수량 + 이름` 순서는 자동 후보가 안 잡힌다(수량 뒤에 단위가 없으므로). 원문과 이름 매칭(`양파`)은 정상이고, "직접 고르기"로 `1/2`를 지정하면 배율도 먹는다. 자동화만 미지원.
- [ ] **앞자리 0을 생략한 소수** — `.5컵` 표기는 자동 탐지도 수동 지정도 안 된다(`NUM`이 `\d+` 시작을 요구). 숫자 앞 `.`·`,` 차단은 `물 1,000ml` → `000ml`(qty 0) 오탐을 막는 가드와 **같은 장치**라 따로 풀 수 없다. 한국어 레시피에서 `0.5컵`/`1/2컵`이 표준이라 우선순위 낮음. 2026-08-14 검증에서 확인.
- [ ] **생성 rate limit 조정** — 현재 같은 IP 30초 1회(구현 완료, 기획서는 MVP 제외였음). 공유 IP(회사·카페)에서 과하면 완화 검토.
- [ ] **레시피 삭제** — 지금은 생성 후 지울 수 없다. "내 레시피"에서 지우는 건 목록에서만 빠지고 D1 row는 남는다. 소유자 삭제(DELETE + editToken) 필요.
- [ ] **단계 재배열 UI** — 지금은 textarea 줄 편집으로만.
- [ ] **조리 모드 타이머 다중** — 한 단계에 타이머 하나만(첫 매칭). "10분 볶고 20분 끓인다"는 앞의 10분만 잡는다.

## 공유 드래그 hook (`lib/ui/use-sortable.ts`) — 허브와 공용

0.3.0에서 재료 정렬에 쓰려고 `lib/hub/`에서 옮겨 왔다. 정찰에서 확인된 결함 2건은 **허브 기본값을 바꾸지 않으려고** recipe-note만 옵션으로 옵트인한 상태다. 허브도 고치려면 별건으로:

- [ ] **터치 long-press가 이동으로 취소되지 않음** — 허브 홈에서 즐겨찾기 위를 스크롤하면 300ms 뒤 카드가 들린다. recipe-note는 `cancelTouchOnMovePx: 10`으로 회피 중. 허브 기본값을 바꾸려면 실기기 확인 필요(테스트 없음).
- [ ] **`pointercancel`이 순서를 커밋함** — 시스템 제스처·스크롤 탈취로 취소돼도 마지막 `overIndex`로 정렬이 반영된다. recipe-note는 `abortOnPointerCancel: true`로 회피 중.
- [ ] **활성 후에야 `touch-action: none`** — 브라우저는 touch-start에 값을 확정하므로 드래그 중 페이지가 같이 스크롤될 수 있다. `components/language-maker/character-grid.tsx`의 non-passive `touchmove` 방식이 repo 내 해법.
- [ ] **키보드 정렬 없음** — 포인터 전용. 폼 필드 목록에서는 더 아쉽다.
